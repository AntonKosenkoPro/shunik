# Timetracking — FURPS

Requirements for the **account-bound local-first sync architecture** (OpenSpec change `account-bound-local-data`): the device is the source of truth, the backend is the identity + sync relay, and **sign-in is mandatory** before any tracking use — the app shows a restoring splash while the launch session restore resolves, then the auth flow (email-OTP or Sign in with Apple), then works fully offline. There is no anonymous use: local data is per-account (`lifio_<userId>.db`, one active file, dormant files kept), sessions are per-device, and sync is same-account-only.

App-wide requirements (minimalism, dark/light, offline, EN+RU localization, HIG, secure storage, linters, tests, CI, OpenAPI, `AGENTS.md`) live in [`Common.md`](./Common.md) and are not repeated here; only feature-specific rows are listed.

| F1    | The **local device is the source of truth**: entries, categories, and the running timer state live in a **per-account** local SQLite database (GRDB) in the App Group shared container (`group.com.antonkosenko.timeoflifeapp`) — `lifio_<userId>.db`, one file per account, one active file at a time (active marker keyed on `user_id`). Starter categories seed **per account file** on first open. After the mandatory sign-in, all app features work fully with no network connectivity. Dormant (non-active) account files are kept: logout keeps them, re-login as the same account reopens and resumes (outbox drains, cursors continue, timer draft resumes). | The backend is the identity + sync relay, not the authority. Anonymous use is removed: no signed-in account, no app shell. The active database is accessible cross-process (widgets, Screen Time extension, lock-screen Control intents) and after first-unlock-since-boot (`.completeUntilFirstUserAuthentication`). Only the explicit per-account Erase deletes the active file. |
| F2    | Every local mutation (create, update, delete) writes the state change **and a transactional outbox row in one transaction**. Deletes are first-class (the outbox row persists after the record is gone). The outbox survives relaunch. | Each outbox row maps to one idempotent POST / LWW PATCH / hard DELETE on the relay. `LocalStore` is the single chokepoint for all mutations — no raw GRDB writes outside it. |
| F3    | Deletions enter a **durable undo buffer** (full serialized snapshots) and remove the records in one transaction; a buffered deletion stays restorable until the app restarts. No outbox row is created while a deletion is in the buffer. | Buffered rows commit on **cold launch** (never while the process is alive; no background timer). The buffer survives suspension and backgrounding. Supersession per U7: only the most recent buffered deletion is restorable; older ones stay buffered until undone or the app restarts. |
| F4    | The **running timer state** (`activity_text`, `category_ids`, `started_at`, `status`) is persisted in a `timer_state` singleton row in the local database, not just in memory. | The running timer survives app crashes; widgets and lock-screen Controls read the same row to render running state and elapsed time. |
| F5    | **Sync is session-gated and same-account-only**: the `SyncController` activates on `.signedIn` and deactivates on `.signedOut`; it records the bound `userId` at activation and refuses/skips cycles on account mismatch — it never pushes one account's outbox under another account's token. Sync is not optional for use of the app (sign-in is mandatory), but the tracker works fully offline once signed in. | Sign-out keeps every account file (Keychain/cache/session cleared, DBs untouched, dirty outbox and a running timer stay in the dormant file); an explicit per-account "Erase local data" action deletes only the active account file. |
| F6    | **First-sync is pull-first**: on activation, pull the relay's full state, merge server-wins on `updated_at` conflicts, then drain the local outbox. | Lets the relay's ids arrive before local pushes, so cross-device name collisions mostly resolve during merge rather than on push. |
| F7    | **Delta pull-sync** via `?modified_since=` (RFC 3339) on `GET /entries`; the client follows relay pagination (`limit` + `cursor`/`next_cursor`) to exhaustion on every pull and advances the entries cursor to the max `updated_at` over ALL pages received — never to a partial-page max. Cursors recorded before pagination-aware pulls are discarded exactly once per account file (one-time re-baseline → full re-pull through the idempotent merge; fresh installs are unaffected). `GET /categories` is a full pull ordered by name (no `modified_since` — the handler ignores it; adding it is a backend follow-up, not this contract). | Absent/empty `modified_since` = full pull. Integrations (hundreds/thousands of entries) don't force full re-pulls. |
| F8    | **Last-write-wins conflict resolution on `updated_at`**: on pull, apply a server record only if `server.updated_at > local.updated_at`; on push, 409 `conflict` → adopt the server version (keep-latest) and clear the outbox row. 409 `category_exists` → re-map local references to the winning id. | Outbox drain is idempotent (one HTTP call per row, in `created_at` order); replays after crash/relapse are safe. |
| F9    | **Sync triggers**: app enters foreground, connectivity restored (`.satisfied`), manual "Sync now" in Profile, and pull-to-refresh on the populated History list (sync-only; the empty state offers no pull). A trigger arriving while a cycle is in flight joins it instead of starting a second cycle. A "Last synced"/"Syncing…"/error status is visible in Profile. | No background task scheduling on iOS (unreliable); macOS may add a timer-based background sync later. The user is always signed in (mandatory gate), so no signed-out pull state exists; offline pulls show an inline offline banner (no cycle); pull-awaited failures show an OK-only dialog. |
| F10   | **Entry provenance**: every entry carries `source` (enum: `manual`, `widget`, `siri`, `control`, `screentime`, `garmin`, `calendar`, `healthkit`; default `manual`) and nullable `source_ref` (external id, e.g. Screen Time callback uuid, Garmin activity id). | Persisted locally and propagated through the outbox and relay. |
| F11   | **Duplicate import prevention**: `UNIQUE(user_id, source, source_ref)` for non-null `source_ref`; a source re-sending the same record (Screen Time firing twice, Garmin re-sync) is rejected with 409 `duplicate_import`. | Deleting an imported entry is a hard delete; a later re-import of the same `(source, source_ref)` does not resurrect it. |
| F12   | **Lock-screen Controls** (iOS 18+): a WidgetKit `ControlWidget` toggle starts/stops the timer from the lock screen, Control Center, or Action button without opening the app or Face ID, via an `AppIntent` with `authenticationPolicy = .alwaysAllowed` writing to the App Group database. | Default action: toggle the most-recently-used text. ControlWidget itself not yet offered (deferred — though a widget extension target now exists for Live Activities, F15); deployment target is iOS 18, no availability guards. Control-started entries carry `source='control'` and enqueue an outbox row in the same transaction. |
| F13   | **Manual entry logging**: a Calendar-style Log Time sheet (Name + Start + End + Categories + Notes in that order, Start/End as separate cards with inline single-open date/time pickers, Add gated on trimmed non-empty name + floor rule (untouched drafts: end after start; edited drafts: end at least one minute after start)) reachable from the History toolbar `[+]`. Saves a committed `source='manual'` entry via the transactional outbox (F2); overlaps and future end-times allowed. Moving Start shifts End by the same delta in both directions (duration preserved); the End pickers offer nothing before Start plus one minute (same-day time wheel bounded, later days open). Sub-minute EDIT prefills display floor(start) / floor(start)+1m with the true duration in the subtitle and save untouched unless a time picker is touched (first touch adopts the displayed pair). Untouched drafts with seconds display minute-floored pills with the true subtitle; the first touch minute-normalizes both ends (floor both — never below one minute for ≥60s drafts) and then applies the gesture. All native gestures work in the form (pull-down-to-scroll with any picker open or closed, swipe-down-to-dismiss the sheet, edge-back pop of the pushed form, tap-away/scroll-away keyboard dismissal) — no gesture is disabled for layout. | History row taps push the same unified entry form onto the History navigation stack (EDIT for `manual`, LOCKED read-only for imported with delete only); destructive Delete names the entry text, enters the durable undo buffer with shake-to-undo (no toast). | F14   | **Cross-device delete propagation**: every hard DELETE records a `(resource, record_id, deleted_at)` tombstone on the relay in the same transaction (cascade children get none; recreating an id clears its tombstone); `GET /deletions?deleted_since=` lists them oldest-first. Every sync cycle applies tombstones before draining: delete local rows with no outbox row, drop stale pending create/update rows (delete-wins over concurrent offline edits), keep pending DELETE rows (404-as-success converges them). A clean local row newer than the tombstone is a recreation that won and is kept. Pushes for tombstone-less relay-missing records resurrect from local data and retry once (entry re-posts as create, missing parents re-post first, updates re-post as create) instead of wedging; updates for locally-missing records drop pre-push. Stopping a timer whose draft references categories deleted elsewhere prunes the unknown ids and keeps the remainder (no entry is lost). | Pull-merge and conflict adoption stay delete-wins for not-yet-converged local deletions (buffered or pending outbox DELETE). ## Resolved decisions

- **Local store** (D1): GRDB.swift in the App Group shared container `group.com.antonkosenko.timeoflifeapp`, data protection `.completeUntilFirstUserAuthentication` (default). SwiftData (iOS 17+ only) and Core Data rejected.
- **Outbox** (D2): a separate `outbox` table holding operations (op, resource, record_id, payload, created_at), not a per-record `sync_state` column (deletes would need a tombstone table).
- **Undo buffer** (D3): durable `undo_buffer` table restorable until restart; commit-on-cold-launch; no background timer. A wall-clock expiry window was tried and removed (it expired before users found the shake gesture).
- **First-sync** (D4): pull-first (full pull + server-wins merge, then drain the outbox). Push-first rejected (409 name-collision remapping during push is more complex).
- **Backend additions** (D5): additive only — `modified_since` query param + nullable `source`/`source_ref` columns; no contract break.
- **SyncController** (D6): `@MainActor`, long-lived, session-gated; observes `SessionStore` and `Connectivity`; exposes `@Published status`; records the bound `userId` and refuses cycles on account mismatch.
- **RootView** (D7): gates on `SessionStore` — restoring shows a splash (never the auth flow), signed-out renders the auth flow full-screen, signed-in renders the app shell only after the account file is bound, buffered deletions committed, and starter categories seeded (seed-before-reveal; first-sync pull stays background and Track converges via its sync-exit reload). Anonymous use is removed; auth is the launch gate, not a Profile action.
- **Running timer state** (D8): `timer_state` singleton row in GRDB.
- **Lock-screen Controls** (D9): iOS 18+ `ControlWidget` + `alwaysAllowed` AppIntent, deferred (no widget target); deployment target is iOS 18, no availability guards; reads/writes the active account file post-first-unlock, no auth of its own.
- **Account-bound store** (D11): per-account files `lifio_<userId>.db` (one active at a time, active marker = `user_id`); dormant files kept, no eviction; per-account seeding on first open; explicit per-account Erase deletes only the active file; per-account data migration rejected (pre-release discard).
- **Per-device sessions** (D12): stable Keychain UUID as `X-Device-Id` (not `identifierForVendor`); per-device refresh families; reuse-detection and logout revoke only that device's family; refresh TTL enforced at the refresh handler; revoked/exhausted sessions lock to the auth gate — never wipe (lock-not-wipe). No `device_limit` in the API (quota + picker deferred to #46); no multi-session switcher (every switch re-authenticates).
- **Source labels** (D10): user-visible localized "via <Source>" labels for non-`manual` sources.
