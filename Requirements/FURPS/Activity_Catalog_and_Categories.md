# Entry Text & Categories — FURPS

Requirements for **entry-owned text and category tags** (OpenSpec change `remove-activities-layer`): there is no activity entity. Every entry owns its trimmed `activity_text`, its ordered `category_ids`, and its `notes` at write time; history never mutates retroactively. The Track screen offers a plain-text field plus recency chips computed on-device from past entries.

App-wide requirements (minimalism, dark/light, offline, EN+RU localization, HIG, secure storage, linters, tests, CI, OpenAPI, `AGENTS.md`) live in [`Common.md`](./Common.md) and are not repeated here; only feature-specific rows are listed.

[^1]: The typed text is a first-class identity: it appears in Recents next time and inherits its categories on exact match. The user is never forced to open a catalog to start a timer — typing a name and starting still works in one step (F4).

## Resolved decisions

- **Sync conflict policy** (R2): last-write-wins on `updated_at`; no field-level merge at MVP.
- **Seed set** (F6): 7 categories — Work, Hobby, Sport, Education, Relax, Sleep, Entertainment (EN/RU). No starter entries.
- **Limits**: no count caps enforced at MVP; name ≤ 60 chars, notes ≤ 2000 chars.
- **No activity catalog** (`remove-activities-layer`): F7/F8 removed; there is no activity search, quick-create, Manage Activities, or activity editor anywhere in the app.
