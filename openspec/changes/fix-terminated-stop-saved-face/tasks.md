## 8. Ticking-while-idle race (physical-device finding 2026-10-11)

- [x] 8.1 Diagnose: Track digits follow `vm.elapsed` (ticker) while everything else follows `vm.state` — consistent only by convention. A `load()` landing inside `stop()`'s save-await saw the still-persisted draft and revived `.running` over `.saving`, starting a ticker the already-run `stopTicker()` never kills (digits climb through `.saved` into `.ready`). Banner-Link opens make it likely (foreground + handler + sync-exit reload volley). Same family: `select()` never excluded `.saving`, so a mid-save chip tap flipped to `.ready` and the completing `stop()` no-op'd (run never saved).
- [x] 8.2 Fix + repro tests (`TrackSyncReloadTests`, `stopGate` hook nil in production): revive skips when `state.isSaving`; `stop()` stops the ticker again after the save; `select()` guards `isSaving`. Both tests recorded failing pre-fix (revive clobber + elapsed growth; chip-tap flip) and pass post-fix. `swiftlint --strict` 0 violations; `TimeOfLifeTests` 653/653 green.
